## 2. 改善提案（優先度順）

### P1: 仕様書と現行レイアウトのドリフト解消（実装引き渡しのブロッカー）

`docs/v2_rules_summary.md` §1（2026-04-25 凍結）と現行プレビューが食い違っています。

| 項目 | 仕様書の記述 | 現行プレビューの実態 |
|---|---|---|
| 開発フローでの位置 | 右ページ（6 視点の下） | **左ページ下段**（メイン図の下） |
| メイン図 | Before/After 図 + 擬人化ポンチ絵の 2 枠 | **「イメージ」1 枠に統合**（最終画像差し込み済み） |

Astro + React の実装担当は `v2_rules_summary.md` と `component_spec_v2.md` を単一真実点として渡される前提なので、このまま渡すと**古いレイアウトが実装されます**。

**やること**: 現行プレビュー（`scripts/preview_gen.py` の出力）を正として v2.29 を起こし、`v2_rules_summary.md` §1・§4、`component_spec_v2.md`、`entry_schema.yaml` の 3 点を同期。§7 の解消済み項目もクローズする。あわせて `CLAUDE.md` §2（「本書き 14 件」のまま）と `ledgers/next_session_handoff.md`（v11 = 5/23 のまま）も現状に更新する。

### P2: 誌面に出てしまう品質バグの一掃（原稿側・機械化可能）

1. **参考 URL 未記入 65 件**: ready なのに誌面へ「参考（未記入）checked —」が印字される状態。`validate_entry.py` に「ready / needs_review で出典メモに URL 0 本 → ☆ 違反」を追加し、65 件を棚卸しする（人物・国産 YouTuber 系は公式チャンネル URL で埋まるはず）。
2. **⚠️ 139 件の大半を占める reader_level 幅ルール**: 「幅 2 段以上（2-4 等）は警告」のルールと実データが噛み合っていません。方針を決めて一掃を推奨します。推奨は**データ側を寄せる**（2-4 → 中央 1 段幅へ）ですが、実態優先でルール側を「幅 2 まで許容」に緩める判断もあり得ます。どちらでも、ノイズが 139 件あると本当の警告が埋もれるのが問題です。
3. **時変情報の鮮度 305 件**: モデル・料金を含むのに評価日が 3 ヶ月以上前。全件書き直しは不要で、まず「checked から N ヶ月経過で ⚠️」を revision_queue に出す仕組みを足し、刊行前に letter 単位で棚卸しする運用を提案します（B 料金系・D モデル系が優先）。

## 3. 追加でやるべき内容候補（バックログ提案）

効果と手間で並べています。上 3 つはこのプロジェクト（markdown + 検証）内で完結します。

1. **全 364 件の実寸オーバーフロー監査を自動化**（効果大・手間小）
   今回の実測はサンプル 10 件です。`preview_to_pdf.py` 相当の scrollHeight 実測を全件回すスクリプトを `scripts/` に常設し、revision_queue に「はみ出し」列を足す。将来は GitHub Actions で PR ごとに回すと、原稿を伸ばした瞬間に検知できます。
2. **関連用語ピルのリンク解決率監査**（効果中・手間小）
   related_terms が実在エントリ ID / タイトルに解決できるかを全件チェック。書籍では相互参照の破れ、Web 版ではリンク切れになる箇所を刊行前に把握します。
3. **章ごとの視覚変化点の仕様化**（効果中・手間中、§7 の積み残し）
   339 見開き同型の単調さ対策。新しい色を増やさずにできる範囲として、（i）章扉スプレッド 10 枚、（ii）チロムの章アイコン（現行のメダル絵柄の体系化）、（iii）小口側の章インデックス帯（爪掛け）の 3 案を推奨。仕様だけ固めて実装担当へ。
4. **Web 版の読者導線**（効果中・手間中）
   `drafts/index.html` は管理用の全ページ一覧で、読者向けの入口ではありません。`drafts/search/index.json` と `reading_routes` が既にあるので、「検索 → 見開き」「レベル別・ルート別の入口」を読者向けトップとして 1 枚に統合する価値があります。750px 固定幅なのでスマホでの閲覧体験（横スクロール）も要判断です（誌面はそのまま・ビューアで縮小、が現実的）。
5. **印刷前工程の消化**（効果大・時期依存）
   §7 の残り: bleed 3〜5mm、CMYK 色校正、Zen Maru Gothic の埋め込み確認。`build_galley_pdf.py` で束見本 PDF を定期生成し、ページ数（現状 physical page 番号で 570 頁前後まで振られています）と綴じの現実性を著者が確認するタイミングを一度作るのを推奨します。
6. **evaluation_date 更新スプリント**（効果大・手間大）
   P2-3 の仕組みを入れた後、B（料金）→ D（モデル）→ C（企業）の順で letter 単位に評価日を更新。entry-writer の並列運用ノウハウがそのまま使えます。
