# パラメータ数の単位

## tagline

「7B」「70B」のBやMなど、モデルの規模を表す数の単位です。


<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

パラメータはモデルが学習で身につけた数値の集まりで、その個数が規模の目安になります。表記は B＝Billion（10 億）、M＝Million（100 万）、T＝Trillion（1 兆）で、「Llama 3 8B」なら約 80 億個という読み方です。

## どこで出会うか

Hugging Face のモデルカードや ollama で扱うモデル名に「7B」「13B」といった表記が並びます。新モデル発表のニュース記事でも、規模の大きさを伝える数字として使われます。

## メイン図

### 図の狙い

M・B・Tの桁とモデル名の実例を並べ、数字の読み替え方を一目で掴んでもらう。

### B. 登場シーン（figure_type: comparison）

- シーン1: M（Million＝100 万）の桁 — 小型モデルの規模
- シーン2: B（Billion＝10 億）の桁 — Llama 3 8B や 70B の規模
- シーン3: T（Trillion＝1 兆）の桁 — 超大規模モデルの規模
- 並べる基準: 桁が上がるほど数字も規模も大きくなる順

## 会話での使い方例

「7B なら手元でも動きますが、70B は API 頼みになりますよね。」


<!-- ━━━━━━━━ 右ページ ━━━━━━━━ -->

## この用語の見どころ

### 1. 役割

B・M・Tでモデルの規模をひと目で示す表記です。

### 2. うれしさ

モデル名を見ただけで規模感がつかめます。

### 3. 注意点

パラメータ数が多いほど賢いとは限りません。

### 4. どこで役立つか

モデル選びやスペック相談で目安になります。

### 5. はじめに

B＝10億という換算だけ覚えれば十分です。

### 6. 深掘り先

量子化、スケーリング則、VRAM


## 開発フローでの位置（必須）

1. モデル名を見る — 「7B」「70B」の表記に気づく
2. 単位を換算する — B を 10 億に置き換える
3. VRAM 目安を考える — 量子化すれば規模より小さく動く
4. 数字を鵜呑みにしない — 大きさと賢さは別の話と理解する

## コミュニティ補完メモ

- J-19 量子化との住み分け：J-22 は「B・M・T という数字の読み方」、J-19 は「その数字が大きいモデルを手元で動かすための圧縮手段」。本文では量子化の仕組みそのものには踏み込まず、関連用語として橋渡しするだけにとどめる
- J-35 スケーリング則との住み分け：J-22 は単位の読み方という表記の話、J-35 は「規模を増やすとなぜ性能が伸びるか」という傾向の話。本文では触れず深掘り先に置く
- J-70 VRAM との住み分け：VRAM の説明自体は J-70 に譲り、本文では「パラメータ数が多いほど必要な VRAM も増えやすい」という関係だけをひと言添える程度にとどめる
- D-40 Llama 系との住み分け：個別モデルの性能・仕様には踏み込まず、「7B」「70B」という表記の実例としてのみ引用する

## 備考

商用の大手モデル（例: 主要チャットサービスの最新モデル）はパラメータ数を公表しないことが多く、B/M/T 表記が見られるのは主にオープンモデルの世界であることに注意。パラメータ数と性能の関係は学習データや学習手法にも左右されるため、「大きい＝賢い」と断定しない書き方にしている。
