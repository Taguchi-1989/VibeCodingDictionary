## tagline

LLM（大規模言語モデル）を包むシステム全体を設計する工学です。ループ・ツール・メモリ・サンドボックスまでを含む「器」を作ります。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

ハーネス（harness、モデルを包む器・馬具）エンジニアリングは、LLM 単体ではなく、その周りに組む仕組み全体を設計する営みです。何を繰り返すか（ループ）、何を見せるか（コンテキスト）、何を触らせるか（ツール・サンドボックス・権限）を一つの器として組み立て、モデルを「OS の上で動くプロセス」のように扱えるようにします。Claude Code のような実装は、この器が具体化した姿です。

## どこで出会うか

「LLM を新しい OS と見なす」という言い回しとセットでこの言葉に出会います。Anthropic やエージェント基盤の解説記事、あるいは自律ループ（ralph、ultrawork など）の設計論を読み進めた先に、ループ工学・コンテキスト工学よりも一段上の概念として登場します。個々のループ設計やコンテキスト圧縮の工夫を「全部まとめて何と呼ぶか」を探したときに行き着く言葉です。

## メイン図

### 図の狙い

LLM という「中身（プロセス）」を、ハーネスという「器（OS 相当）」が包み込み、その器の内側にループ工学・コンテキスト工学という 2 つの専門領域が入れ子になっている構造を見せる。3 つの工学の上下関係を一目で掴んでもらう。

## 会話での使い方例

「ループもコンテキストも、結局はハーネス設計の一部なんですよね。」

<!-- ━━━━━━━━ 右ページ ━━━━━━━━ -->

## この用語の見どころ

### 1. 役割

LLM を包むシステム全体を設計し、モデルを OS 上のプロセスのように動かします。

### 2. うれしさ

ループ・コンテキスト・ツール・権限をバラバラに考えず、1 つの器として統一設計できます。

### 3. 注意点

抽象度が高く、ループ工学やコンテキスト工学と混同されやすい上位概念です。

### 4. どこで役立つか

Claude Code のようなエージェント基盤を自作・評価するときの設計軸になります。

### 5. はじめに

「LLM を新しい OS と見なす」の一言から、器の中身を分解していくと掴めます。

### 6. 深掘り先

ループエンジニアリング、コンテキストエンジニアリング、サンドボックス、権限モデル、Tool Use

## 開発フローでの位置（必須）

1. モデル選定 — 器の中身となる LLM（推論力・コスト）を決める
2. 器の骨格設計 — ループ・メモリ・ツール・サンドボックス・権限の枠組みを組む
3. ループ設計 — 何を繰り返し、いつ止めるかをループ工学として詰める
4. コンテキスト設計 — 各周回でモデルに何を見せるかをコンテキスト工学として詰める
5. 検証と運用 — ガードレール（反復上限・予算・人間チェックポイント）を敷いて実運用に回す

- **図A: 玉ねぎの層構造（本エントリのメイン図）**
  - 同心の入れ子を「モデルからの距離」順に: 核=LLM（ステートレスな一問一答）→ 第1層=コンテキスト管理（毎回の呼び出しで何を見せるか）→ 第2層=ループ（done まで繰り返す）→ 第3層=ガードレール（停止条件・予算・承認待ち）→ 第4層=ルーティング／デファーラル（誰にやらせるか・限界なら外へ出す出口）→ 最外枠=ハーネス（＋ツール・権限・サンドボックス・観測の資材チップ）
  - 各層の右肩に「解く敵」を明記: 核=一問一答の限界／第1層=敵②文脈溢れ／第3層=敵①終わりが分からない／第4層=敵③コスト・能力の限界。「層は飾りでなく特定の敵への対抗手段」が図の主張
  - 上に「人間①方向づけ（ゴールと done の定義）」帯、下に「人間②承認・③検収」帯。③には「敵④自動化が進むほど負担が集中」と添える
  - 注記: 「ハーネス全体の単位では良し悪しを評価しない。評価は層の単位で」
- **図B: 会社スケールの運用アーキテクチャ（将来の検収系エントリ用・裏台帳保管）**
  - 最外枠=会社（AIマネジメントシステム ISO/IEC 42001 = J-54 で統治）。上に人間①方向づけ帯
  - 左レーン=実行（図Aの玉ねぎを圧縮表示）、右レーン=検証（別軸・独立のチェックボックス: 自動テスト／様式照合／LLM判事／未達は差し戻し）。「すべて☑になるまで人は出てこない」
  - 下に人間②③帯「付いたチェックを見るだけ（判断→確認に圧縮）＋抜き取りで検証レーン自体を監査（較正）」
  - その下に「チェックリストの PDCA」箱: フィードバックで項目追加・腐食した項目は捨てる・チェックリスト＝組織の暗黙知が形式知になった資産
  - 最下段に破線枠「この一式が上位組織のサブエージェントになる（フラクタル）→ 一人社長の範囲が広がる」

## コミュニティ補完メモ

- 同じ Lv6 シェルフの近接語との住み分け:
  - ループエンジニアリング: ハーネスの内側にある一専門領域。「何を繰り返し、いつ止めるか」を担う。本エントリはその上位の器全体。
  - コンテキスト管理: ハーネスの内側にあるもう一つの専門領域。「各周回で何を見せるか」を担う。
  - 自律ループとガードレール: ハーネス設計が実運用に落ちた際の安全装置（反復上限・予算・人間チェックポイント）。
  - Subagent / Tool Use: ハーネスが提供する具体的な仕組みの一部。器の中の部品にあたる。
- スコープ境界: 本エントリは「ハーネスとは何か・3 工学の関係」までを担う。ループの進化史やコンテキスト圧縮の技術詳細は各深掘りエントリに譲る。
