## tagline

LLM は本来ステートレス（記憶を持たない一問一答）です。その外側に「何を繰り返すか」を設計する工学です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

LLM（Large Language Model、大規模言語モデル）は本来ステートレス（stateless、直前のやりとり以外の記憶を持たない一問一答の仕組み）です。ループエンジニアリングは、この一問一答の外側に「何を繰り返すか」「いつ止めるか」を設計する工学で、Perceive（知覚）→Reason（推論）→Plan（計画）→Act（実行）→Observe（観察）というサイクルをどう組むかを扱います。Claude Code の自律実行や ralph（OMC のループ実行モード）は、この設計思想を実装に落としたものと言えます。

## どこで出会うか

「AI にコードを書かせて放置していたら止まらなくなった」「同じ修正を延々繰り返して前に進まない」——こうした場面の裏側にあるのがループの設計です。Claude Code の自律実行や `/goal` コマンド、OMC の ralph・ultrawork のようなツールに、ループエンジニアリングの考え方が組み込まれています。より広い「ハーネスエンジニアリング（モデルを包むシステム全体の設計）」の一部として、コンテキストエンジニアリング（各周回でモデルに何を見せるか）と並ぶ位置づけで語られることが増えてきました。

## メイン図

### 図の狙い

ReAct（2022）→ Reflexion → Plan-and-Execute → 内側・外側の二重ループ → Ralph Loop（2025）→ ネイティブ実装（2026）という進化を 1 本の時系列で並べ、各段階が「何につまずき、次の段階が何を解決したか」を一目で掴んでもらう。

## この用語の見どころ

### 1. 役割

LLM の外側で「何を繰り返し、いつ止めるか」を設計する工学です。

### 2. うれしさ

一問一答しかできない LLM に、長時間の自律作業をこなさせる土台になります。

### 3. 注意点

文脈が溢れる・コストが爆発するなど、回すほど新しい敵が出てきます。

### 4. どこで役立つか

Claude Code・ralph・ultrawork など自律実行系ツールの仕組み理解に役立ちます。

### 5. はじめに

まず「終わりが分からない」問題への対処（停止条件の設計）から押さえると分かりやすいです。

### 6. 深掘り先

ReAct、Ralph Loop、コンテキストエンジニアリング、ガードレール設計、モデル使い分け

## 開発フローでの位置（必須）

1. 検証可能ゴールの設定 — テスト通過など、機械が判定できる完了条件を上流で決める
2. ループへの翻訳 — ゴールを Perceive→Reason→Plan→Act→Observe の繰り返しへ落とし込む
3. 実行と観察 — 各周回でツールを呼び出し、結果を観察して次の判断材料にする
4. ガードレールでの制御 — 反復上限・コスト予算・無進捗検知で暴走を防ぐ
5. 完了判定と停止 — 検証可能な条件が満たされた時点でループを抜ける

- 描く内容: 横一本の時系列レールに 6 つの駅（ReAct 2022 / Reflexion / Plan-and-Execute / 二重ループ(OODA) / Ralph Loop 2025 / ネイティブ実装 2026）を並べる。各駅の下に「敵（つまずき）」を小さな障害物アイコンで、次の駅への矢印に「対抗策」を短いラベルで添える。二重ループの駅だけ「★最大の敵＝文脈が溢れる」を強調する印を付ける。

## コミュニティ補完メモ

- 本エントリは「ループ工学」分野の入口・俯瞰役。ReAct・Ralph Loop 個別の仕組み、コンテキストエンジニアリングの中身（コンパクション・memory tool 等）、モデル使い分け（カスケード／ステップ別ルーティング）、小→大への委譲判断、人間の認知ボトルネックといった個別テーマは、それぞれ別の Lv6 深掘りエントリに譲る。本エントリでは「3 つの工学の関係」「進化史の流れ」「3 つの共通の敵」までを扱い、各論には踏み込まない。
- ハーネスエンジニアリング（モデルを包むシステム全体＝ループ・ツール・メモリ・サンドボックス・権限）を親概念とし、ループエンジニアリング（何を繰り返すか）とコンテキストエンジニアリング（各周回で何を見せるか）はその子に位置づく、という上下関係を崩さない。
- Subagent（サブエージェント）は、コンテキスト工学側の代表的な対抗手段（別の文脈窓を持つ子に投げて要約だけ返す）として関連付けるが、実装の詳細は別エントリに任せる。
