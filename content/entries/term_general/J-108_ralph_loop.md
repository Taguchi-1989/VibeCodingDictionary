## tagline

長く回すエージェントの「文脈が溢れる」問題への対抗策です。毎周回ごとにディスクから状態を読み直し、文脈窓（コンテキストウィンドウ）をまっさらにリセットして次に進むループパターンです。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

Ralph Loop は、エージェントに「会話の記憶を文脈窓に溜め込ませない」ための設計パターンです。タスクの進捗・計画・TODO を会話履歴ではなくディスク上のファイルへ書き出し、次の周回に入る前に文脈窓を空にして、そのファイルだけを読み直させます。1 周回ごとに記憶を「持ち越す」のでなく「書き置きから復元する」形にすることで、どれだけ長く回しても文脈窓が満杯にならず、タスクを継続できます。

## どこで出会うか

読者が日常的に使っている OMC（oh-my-claudecode）の `ralph` や `ultrawork` は、この Ralph Loop の実装です。長時間のリファクタリングや大量ファイルの一括修正など「1 回のやり取りでは終わらない」タスクを Claude Code に任せるとき、裏側でこのパターンが働いています。ループの進化史（ReAct → Reflexion → Plan-and-Execute → OODA 二重ループ）の中で「長く回すと文脈が溢れる」という最大の敵に対する 2025 年の解として登場し、2026 年には Claude の `/goal` コマンドのようにツール側へネイティブ実装される流れの手前に位置します。

## メイン図

### 図の狙い

「会話履歴に記憶を積み増していくエージェント（文脈窓がだんだん満杯になり、やがて溢れて動けなくなる）」と「Ralph Loop（毎周回ディスクの状態ファイルを読み直し、文脈窓を空のまま次に進む）」を並べ、なぜ長時間タスクでも詰まらないのかを一目で掴んでもらう。

### A. Before / After（記憶の持ち方の違い）

- Before（会話履歴に溜め込む）
  - 状況: 周回ごとに過去のやり取りをすべて文脈窓へ積み増す
  - 視覚要素（概念）: 文脈窓のゲージがだんだん満タンに近づく。周回を重ねるほど帯が伸びる
  - つまずき: あるところで文脈窓が溢れ、古い情報が失われるか処理が止まる
- After（Ralph Loop）
  - 状況: 各周回の終わりに進捗・TODO をディスクへ書き出し、次の周回は文脈窓を空にしてそのファイルだけ読み直す
  - 視覚要素: 周回ごとに文脈窓ゲージがリセットされ、常に低い水位からスタート
  - うれしさ: 何周回続けても文脈窓が満杯にならず、長時間タスクを継続できる

## 会話での使い方例

「ralph って結局、毎回ディスクから状態読んで文脈窓リセットしてるだけなんですよね。」

## この用語の見どころ

### 1. 役割

毎周回ディスクの状態を読み直し、文脈窓をリセットして次に進むループパターンです。

### 2. うれしさ

長く回しても文脈窓が満杯にならず、長時間タスクを継続できます。

### 3. 注意点

記憶を文脈窓でなくファイルに外出しするため、状態ファイルの設計が甘いと進捗が正しく復元できません。

### 4. どこで役立つか

大量ファイルの一括修正や長時間リファクタリングなど、1 回のやり取りで終わらないタスクで活きます。

### 5. はじめに

OMC の ralph・ultrawork の正体だと知ると、普段使っている挙動がすっと繋がります。

### 6. 深掘り先

コンテキストエンジニアリング、OODA 二重ループ、ハーネスエンジニアリング、/goal ネイティブ実装

## 開発フローでの位置（必須）

1. 状態設計 — 進捗・計画・TODO をディスク上のファイルにどう書き出すか決める
2. 周回実行 — エージェントが 1 周回タスクを進め、結果を状態ファイルへ書き戻す
3. 文脈リセット — 周回の終わりに文脈窓を空にし、会話履歴を持ち越さない
4. 再読込 — 次の周回の冒頭で状態ファイルだけを読み直し、そこから続きに入る
5. 停止判定 — 検証可能な完了条件（テスト通過など）に達するまで 2〜4 を繰り返す

## コミュニティ補完メモ

- 同じ Lv6 シェルフの近接語との住み分け:
  - ループエンジニアリング（J-103）: ループの進化史全体（ReAct → Reflexion → Plan-and-Execute → OODA 二重ループ → Ralph Loop → ネイティブ実装）を扱う上位概念。本エントリはその中の 1 段階、「文脈が溢れる」という最大の敵への具体的な解答という位置づけ。
  - コンテキスト管理（J-105）: 圧縮・メモリツール・サブエージェントなど「限られた文脈窓に何を入れ何を捨てるか」の技法全般。Ralph Loop は文脈窓を「捨てて作り直す」極端な一手法で、コンテキスト管理の一部と重なるが、本エントリは「毎周回リセットする」という設計パターンそのものに絞る。
  - ハーネスエンジニアリング（J-106）: ループ・ツール・メモリ・サンドボックス・権限を含むモデルを包むシステム全体。Ralph Loop はその中のループ設計の一具体例という位置。
  - Context Window（G-5）: 文脈窓そのものの定義（一般読者向け）。本エントリはその文脈窓を「どう使い回すか」の応用パターン。
  - 自律ループのガードレール（J-107）: 検証可能ゴール・停止条件・反復上限など「いつ止めるか」の仕組み。Ralph Loop は「どう続けるか」（文脈溢れ対策）、J-107 は「どう止めるか」で役割分担。
