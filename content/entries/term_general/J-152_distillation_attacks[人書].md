# 蒸留攻撃

## tagline

許可なく他社モデルの能力を大量に写し取る行為です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

蒸留攻撃（distillation attacks）は、蒸留（大きいモデルの出力で小さいモデルを学習させる技術）を、許可なく他社に対して行う行為です。多数の不正アカウントで大量に質問し、とくに思考の過程を集めます。

## どこで出会うか

思考の中身が全部は見えない、一部の API で過去の文脈を書き換えられないといった仕様の理由として出会います。攻撃者でなくても、対策の影響は受けます。

## メイン図

### 図の狙い

「大量に質問 → 思考の記録を集める → 自社モデルを学習」の流れに、対策の関所を差し込み、なぜ思考が要約で返るのかを掴んでもらう。

### B. 登場シーン（figure_type: workflow）

- 左: 不正アカウント群が大量に質問を送る
- 中: 思考の記録が集められ、学習用データになる
- 右: 写し取ったモデルが育つ
- 差し込み: 流れの途中に 4 つの関所（推論の要約・preserved thinking・分類器・利用制限）

## 会話での使い方例

「思考が要約で返るのは、蒸留攻撃への対策の一つですよね。」

## この用語の見どころ

### 1. 役割

他社モデルの能力を無断で写し取る行為です。

### 2. うれしさ

対策を知ると、思考が要約で返るなど仕様の理由が分かります。

### 3. 注意点

技術としての蒸留は悪ではなく、無断で行うのが攻撃です。

### 4. どこで役立つか

思考の要約や API 仕様変更の背景を読むときです。

### 5. はじめに

まず正当な蒸留との違いを押さえ、仕様変更の理由を読みます。

### 6. 深掘り先

蒸留、Thinking モデル、Chain of Thought

## 開発フローでの位置（必須）

1. 大量に質問される — 不正アカウント群が質問を重ねます。
2. 思考の記録が狙われる — 最終回答より教材価値が高いためです。
3. 関所で防ぐ — 要約・検知・遮断・利用制限を組み合わせます。
4. 仕様が変わる — 開発者側に改修が要る場合もあります。

## 備考

- 対策の 4 段（Anthropic 公式で確認）: ①推論の要約（要約で学習したモデルの SWE-bench Verified が 80.4% から 71.8% に下がったと説明）／②preserved thinking（2026-08-31 以降に作られた API アカウントは、過去の思考を保ったまま以前の文脈を書き換えられない）／③2 段階の分類器（誤検知率 0.1% 未満）／④利用制限・アカウント停止（2026-09-24 から、安全装置が回答前にブロックしたリクエストも課金）。
- 効果: 収集されるデータが 90〜99% 減、抽出できる推論トークンが 10〜100 倍以上減、関連アカウント数万件を停止（多くはキャンペーン開始から 2 時間以内）。2026-02 の報告では 2 万件超の不正アカウントのネットワークが確認された。
- 代償: 一部の開発者は連携の改修が必要、まれに正当なリクエストもブロック、売上の減少。Anthropic 自身が「いたちごっこが続く」「業界全体で防ぐ責任を分け合うべき」と述べている。
- 懸念: 写し取られたモデルは安全装置が弱いことがあり、生物・サイバー分野での悪用や軍事・監視システムへの転用につながりうる。
- 方針: 特定の国・企業は名指ししない。
