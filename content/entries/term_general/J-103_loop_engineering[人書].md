## tagline

LLM は記憶を持たない一問一答です。その外側に「何を繰り返すか」を設計します。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

LLM（大規模言語モデル）は本来ステートレス（一問一答で記憶を持たない）です。その外側に「何を繰り返すか」「いつ止めるか」を設計するのがループエンジニアリングで、知覚→推論→計画→実行→観察のサイクルを組みます。

## どこで出会うか

「AI にコードを書かせて放置したら止まらなくなった」——こうした場面の裏側にあるのがループの設計です。Claude Code の自律実行や ralph のようなツールに、この考え方が組み込まれています。

## メイン図

### 図の狙い

ReAct（2022）→ Reflexion → Plan-and-Execute → 内側・外側の二重ループ → Ralph Loop（2025）→ ネイティブ実装（2026）という進化を 1 本の時系列で並べ、各段階が「何につまずき、次の段階が何を解決したか」を一目で掴んでもらう。あわせて図の左下隅に共通のスコープ地図（ミニ図）を置き、ループ工学が担当するのは入れ子の第 3 層であることを示す。

## 会話での使い方例

「Ralph Loop は毎回ディスクから状態を読み直して文脈窓をリセットする発想ですよね。」

## この用語の見どころ

### 1. 役割

LLM の外側で「何を繰り返し、いつ止めるか」を設計する工学です。

### 2. うれしさ

一問一答しかできない LLM に、長時間の自律作業をこなさせる土台になります。

### 3. 注意点

文脈が溢れる・コストが爆発するなど、回すほど新しい敵が出てきます。

### 4. どこで役立つか

Claude Code や ralph など、自律実行系ツールの仕組み理解に役立ちます。

### 5. はじめに

まず「終わりが分からない」問題への対処＝停止条件の設計から押さえます。

### 6. 深掘り先

ReAct、Ralph Loop、グラフエンジニアリング、ガードレール設計

## 開発フローでの位置（必須）

1. 検証可能ゴールの設定 — テスト通過など、機械が判定できる完了条件を上流で決める
2. ループへの翻訳 — ゴールを知覚→推論→計画→実行→観察の繰り返しへ落とし込む
3. 実行と観察 — 各周回でツールを呼び、結果を次の判断材料にする
4. ガードレールでの制御 — 反復上限・コスト予算・無進捗検知で暴走を防ぐ
5. 完了判定と停止 — 検証可能な条件が満たされた時点でループを抜ける

## コミュニティ補完メモ

- 本エントリは「ループ工学」分野の入口・俯瞰役。ReAct・Ralph Loop 個別の仕組み、コンテキストエンジニアリングの中身（コンパクション・memory tool 等）、モデル使い分け（カスケード／ステップ別ルーティング）、小→大への委譲判断、人間の認知ボトルネックといった個別テーマは、それぞれ別の Lv6 深掘りエントリに譲る。本エントリでは「3 つの工学の関係」「進化史の流れ」「3 つの共通の敵」までを扱い、各論には踏み込まない。
- ハーネスエンジニアリング（モデルを包むシステム全体＝ループ・ツール・メモリ・サンドボックス・権限）を親概念とし、ループエンジニアリング（何を繰り返すか）とコンテキストエンジニアリング（各周回で何を見せるか）はその子に位置づく、という上下関係を崩さない。
- Subagent（サブエージェント）は、コンテキスト工学側の代表的な対抗手段（別の文脈窓を持つ子に投げて要約だけ返す）として関連付けるが、実装の詳細は別エントリに任せる。
