# MCP の登録・設定

## tagline

作った・配布された MCP サーバーを、使う側のツールに登録して初めて使えるようにする手続きです。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

作った、あるいは配布されている MCP サーバーは、そのままでは使えません。使う側のツールに登録して初めて呼び出せるようになります。設定ファイルへの追記やコマンドでの登録が、この作業にあたります。

## どこで出会うか

自作した MCP や、公開されているサーバーを試すときに必ず通る手順です。登録先は自分の PC だけ・プロジェクトで共有・ユーザー全体、と範囲を選べ、この設定に API キーなどの秘密を渡す場面も多くあります。

## メイン図

### 図の狙い

MCP サーバーが、設定ファイルへの登録を経て使う側のツールから呼び出せるようになるまでの流れを 1 枚で見せます。「作った・配布された」だけでは使えないことが伝わるようにします。

### C. 概念図（figure_type: workflow）

- 中心に置く概念: 登録・設定（MCP サーバーとツールをつなぐ手続き）
- 周辺の要素（4〜5 個）: 配布・自作の MCP サーバー／設定ファイルまたはコマンド／登録範囲（PC だけ・プロジェクト共有・ユーザー全体）／使う側のツール（Claude Desktop や Claude Code など）／API キーなどの秘密情報
- 関係の描き方: 左に MCP サーバー、中央に登録の手続き（設定ファイルまたはコマンド）、右に使う側のツールを並べる。中央の下に「登録範囲」を分岐で添える

## この用語の見どころ

### 1. 役割

MCP サーバーをツールに紐づけ、使える状態にする手続きです。

### 2. うれしさ

設定ファイルへの追記だけで、すぐに使い始められます。

### 3. 注意点

API キーなど秘密を渡すため、スコープ選びが重要です。

### 4. どこで役立つか

自作や配布の MCP サーバーを導入する場面全般です。

### 5. はじめに

自分の PC だけの scope で 1 つ登録してみることです。

### 6. 深掘り先

MCP Server、MCP Client、API キー

## 開発フローでの位置（必須）

1. 登録先のツールを決める — Claude Desktop や Claude Code など、使う側を選びます
2. スコープを選ぶ — 自分の PC だけ・プロジェクト共有・ユーザー全体から選びます
3. 設定ファイルやコマンドで登録する — 秘密情報を渡す場合は扱いに注意します
4. ツールを再起動して動作を確認する — 呼び出せるかを実際に試します

## 備考

MCP の設定コマンドや設定ファイル名は改訂が速い領域です（Python SDK は 2026-07 に v2 でクラス名が変更、SSE は 2025-03 の改訂で Streamable HTTP に置き換わりました）。本エントリでは特定のコマンド名やファイル名には深入りせず、「登録して初めて使えること」「スコープを選べること」「秘密情報を渡す場面があること」という考え方を扱います。着手時は公式ドキュメントを確認してください。

**著者の指摘（2026-09-06）**: **何でも入れたくなるが、棚卸しをしないと危ない**、というのが核心。

- **危険側**: 何度も入れていくと、**危ないもの・攻撃性のあるものが混ざりうる**
- **有用側**: 一方で、**トークンの消費を減らせるもの**や、**スキル側と連携して効くもの**もある

**この線引きが難しい。**組織としては、**評価された公式のもの以外は基本的に使わない／許可制にする**のが安全だろう、というのが著者の見立て。**個人としては、まず何でも使ってみればよい**とも思っている。**ただしどちらにせよ棚卸しが要る**ので、**「どこかでやめる」という選択肢を含めて、どこまで使っているかを把握しておくことが大事**。

設定作業そのものは、**Claude Code や Codex に任せてしまえばよい**というのが実務の実感。

（I-1 MCP で著者が述べた「**入れすぎるとコンテキストを圧迫する**」の続き。J-146 ゾーンとコンジットの「全部つなげない」とも同じ発想。）
