# API キー

## tagline

API を使う人やアプリを識別する秘密の文字列で、パスワードと同じ扱いが必要です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

サービス側が発行する固有の符号で、リクエストを送るたびに一緒に渡します。誰がどれだけ使ったかを識別し、利用量やアクセス範囲を制限する役目も持ちます。

## どこで出会うか

Google AI Studio や OpenAI の管理画面で発行され、コードや外部ツールの設定欄に貼り付けて使います。誤って GitHub に公開してしまう事故も後を絶ちません。

## メイン図

### 図の狙い

API キーが「使う権利を証明する鍵」であることと、漏れたときに何が起きるかを 1 枚で見せる。

### C. 概念図（figure_type: structure）

- 中心に置く概念: API キー
- 周辺の要素（4 個）: 発行元（Google AI Studio 等）／`.env` での保管／権限・上限の設定／漏えい時のローテーション
- 関係の描き方: 中心の鍵アイコンから 4 つの要素へ矢印が伸びる構造図。鍵を握る開発者と、盗み見ようとする影の人物を対比で添える

## 会話での使い方例

「API キーは `.env` に置いて、GitHub には上げないようにしています。」

## この用語の見どころ

### 1. 役割

そのアカウントの利用権限を示す識別符号です。

### 2. うれしさ

自分のアプリからサービスの機能を呼び出せます。

### 3. 注意点

漏れると第三者に使われ、料金や被害が発生します。

### 4. どこで役立つか

自作アプリや外部ツールから他サービスを呼ぶ場面です。

### 5. はじめに

まずは `.env` に隠す習慣だけ身につければ十分です。

### 6. 深掘り先

.env、GitHub、Google AI Studio

## 開発フローでの位置（必須）

1. キー発行 — Google AI Studio や OpenAI の管理画面で取得します。
2. `.env` へ保存 — ソースコードに直書きせず環境変数として扱います。
3. 権限と上限を設定 — 用途を絞り、料金の使いすぎを防ぎます。
4. 漏えい時はローテーション — 気づいたら即座に無効化し、作り直します。

- F-213 API との住み分け：API そのものの仕組みやエンドポイントの説明は F-213 に譲り、本エントリは「鍵という秘密情報の取り扱い」に絞る。

- B-39 Google AI Studio との住み分け：発行の実物を見せる導線として B-39 を参照し、本エントリでは発行後の扱い方に重心を置く。

## 備考

- キーの権限を絞る機能や利用量の上限設定は、サービスによって名称や有無が異なります。本エントリでは考え方の共通部分のみ扱います。
- 公開リポジトリへの誤コミットは実際に多い事故です。気づいた時点でキーを無効化し、新しいキーに切り替える（ローテーションする）のが基本の対処です。
