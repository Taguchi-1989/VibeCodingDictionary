# リポジトリ

## tagline

ファイルと変更履歴をまとめて保管する、プロジェクト単位の入れ物です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

ファイルとその変更履歴を 1 つの単位にまとめ、自分の PC（ローカル）とサーバー（リモート）の両方に置いて同期できるようにします。1 リポジトリ＝1 プロジェクトが基本の単位です。

## どこで出会うか

「リポジトリを作って」と言われて何を用意すればよいか分からず固まる場面や、AI エージェントに作業を頼む前に「どのリポジトリで進めるか」を聞かれる場面で出会います。

## メイン図

### 図の狙い

ローカルリポジトリとリモートリポジトリが同期でつながっている構造を示し、1 プロジェクト＝1 リポジトリという単位の感覚をつかんでもらいます。

### C. 概念図（figure_type: structure）

- 中心に置く概念: リポジトリ（プロジェクトの入れ物）
- 周辺の要素（4 個）: ローカルリポジトリ（自分の PC）／リモートリポジトリ（GitHub 等のサーバー）／公開（public）・非公開（private）の選択／1 プロジェクト＝1 リポジトリのラベル
- 関係の描き方: 中心に「リポジトリ」を置き、左にローカル、右にリモートを配置、両者を同期の両矢印でつなぐ構造図

## 会話での使い方例

「まずリポジトリを作って、ローカルとリモートを紐づけましょう。」

## この用語の見どころ

### 1. 役割

ファイルと変更履歴をひとまとめにして保管します。

### 2. うれしさ

ローカルとリモートを同期させ、作業を安全に共有できます。

### 3. 注意点

複数プロジェクトを 1 つに混ぜると管理しづらくなります。

### 4. どこで役立つか

チーム開発でも AI エージェントとの作業でも起点になります。

### 5. はじめに

ローカルとリモートの違い、1 リポジトリ＝1 プロジェクトの単位。

### 6. 深掘り先

git（F-50）、GitHub（F-60）、.gitignore（F-56）

## 開発フローでの位置（必須）

1. リポジトリを作成 — ローカルまたは GitHub 上で新しいリポジトリを用意します
2. git で初期化・記録 — ファイルを追加し、変更履歴を刻み始めます（F-50・F-54）
3. リモートと同期 — push・pull でローカルとリモートを揃えます（F-51・F-52）
4. AI に作業を依頼 — どのリポジトリで作業するかを指定してから任せます

## コミュニティ補完メモ

- git（F-50）との住み分け：F-50 は変更履歴を記録する仕組みそのもの。本エントリは「その記録を置く入れ物」であるリポジトリの単位・構造に絞る
- GitHub（F-60）との住み分け：GitHub はリモートリポジトリを預かるホスティングサービス。公開・非公開の切り替えや Issue・PR など GitHub 固有の機能は F-60 台に譲る
- git push（F-51）・git pull（F-52）との住み分け：ローカルとリモートを同期させる具体コマンドは F-51・F-52 に譲り、本エントリは「同期する 2 つの場所がある」という構造だけ扱う
- README.md（F-59）との住み分け：リポジトリの中身を説明するファイルは F-59 で扱う
