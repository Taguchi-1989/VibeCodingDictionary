# Zod

## tagline

TypeScript でスキーマを書くと、その型がそのまま使える検証ライブラリです。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

スキーマ（データの形の定義）を 1 か所に書くと、実行時の値チェックと TypeScript の型定義が同時に手に入ります。型を別ファイルに書き直す二重管理が要らないため、AI が生成したコードでも形のズレに気づきやすくなります。

## どこで出会うか

フォーム入力の検証や API のレスポンス確認、環境変数の読み込みなど「外から来る値」を扱う場面でよく使われます。AI に型安全なコードを頼むと、Zod のスキーマごと提案されることもあります。

## この用語の見どころ

### 1. 役割

書いたスキーマが検証ルールと TypeScript の型を兼ねます。

### 2. うれしさ

型定義を別ファイルで二重に書かなくて済みます。

### 3. 注意点

スキーマが複雑になると、書く量が増えることがあります。

### 4. どこで役立つか

フォーム・API レスポンス・環境変数の検証で使います。

### 5. はじめに

`z.object()` で形を 1 つ書けば、すぐ試せます。

### 6. 深掘り先

TypeScript、JSON Schema、Standard Schema

## 開発フローでの位置（必須）

1. スキーマ定義 — `z.object()` で必要な項目と型を書きます
2. 型を取り出す — `z.infer` で TypeScript の型として使い回します
3. 検証実行 — `.parse()` や `.safeParse()` で実データを確認します
4. エラー処理 — 検証結果のメッセージを画面や AI への指示に反映します

## コミュニティ補完メモ

- F-2 TypeScript との住み分け：F-2 は TypeScript という言語そのもの（型注釈・コンパイル）を扱い、F-211 は「実行時に値を検証しながら、その形をそのまま TypeScript の型として使う」というライブラリ固有の恩恵にフォーカスします。型システム一般の説明は F-2 に譲ります。
- F-210 JSON Schema との住み分け：JSON Schema は言語非依存のスキーマ記述仕様そのものを扱い、F-211 は TypeScript 上でスキーマを書く具体的な手段（コードでの書き方・型推論）を扱います。Zod のスキーマから JSON Schema を書き出す変換機能があることには本文で触れません。
- F-213 API との住み分け：API のリクエスト・レスポンスをどう受け渡すかは F-213 に譲り、F-211 では「受け取った値の形をどう検証するか」に絞ります。
- G-48 Structured Outputs との住み分け：LLM の出力そのものを決まった形で受け取る仕組みは G-48 に譲り、F-211 では受け取った後（またはユーザー入力など）の検証という一般的な用途を中心に書きます。
