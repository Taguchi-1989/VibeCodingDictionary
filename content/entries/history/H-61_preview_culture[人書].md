# Preview 版という文化

## tagline

完成を待たずに公開し、使われながら直していく AI 業界の進め方です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

AI サービスの多くは完成を待たずに Preview（プレビュー）版として先に公開します。実際に使われて初めて弱点が見つかる製品特性と、開発競争の速さが背景です。読者はこの流れを知っておくと、名前や機能が変わっても慌てずに済みます。

## どこで出会うか

「（プレビュー）」という表示や、機能追加のお知らせ、突然のサービス名変更として出会います。Claude Code も最初はリサーチプレビューとして公開されました。

## メイン図

### 図の狙い

「未完成のまま出して、使いながら直していく」という進め方を、提供側の事情と利用者の体感の両面から見せます。

### C. 概念図（figure_type: structure）

- 中心に置く概念: 「未完成のまま出す」という進め方
- 周辺の要素: 提供側（実地フィードバック・競争の速さ）と利用者側（早く試せる／振り回される）
- 関係の描き方: 中央のラベルから左右に「利点」「困りごと」の矢印を伸ばす対比構造

## 会話での使い方例

「Claude Code も最初はリサーチプレビューだったんですよね。」

## この用語の見どころ

### 1. 役割

未完成でも先に出し、使われながら直す進め方です。

### 2. うれしさ

無料や割安で最新機能を早く試せます。

### 3. 注意点

名前や機能が予告なく変わることがあります。

### 4. どこで役立つか

新機能を試すか様子見するかの判断に役立ちます。

### 5. はじめに

「（プレビュー）」の表示を意識するだけで十分です。

### 6. 深掘り先

Preview から正式版への流れ（H-51）、AI エージェント元年（H-59）

## 開発フローでの位置（必須）

1. プレビュー公開 — 完成前の機能を限定的にまず先行公開します。
2. 早期利用 — 好奇心のある人がリスクを承知で試し始めます。
3. フィードバック反映 — 使われた結果を受けて仕様が調整されます。
4. 名称・機能の変化 — 改善の過程で名前や中身が変わることがあります。
5. 定着の判断 — 重要な業務に使うかは GA 後まで見極めます。

## 誌面ポンチ絵メモ

### メイン図（左ページ中段 / figure_type: structure）

- 描く内容: 中央に「Preview」の看板を持ったサービスのイラスト。左側に提供側（開発者）が「使ってもらってから直したい」、右側に利用者が看板を見て戸惑う／喜ぶ両方の表情を見せる対比構造。
- 登場人物（いれば）: 左に開発者（看板を掲げている）、右に利用者（「あれ、名前変わった？」と驚く人と「無料で試せてラッキー」と喜ぶ人の 2 パターン）
- 吹き出し・心の声: 開発者「まず出して、直しながら育てます」、利用者（驚き）「昨日と機能違う…」、利用者（喜び）「最新機能がもう使える！」
- 中央に置くキーワード/ラベル: PREVIEW（未完成のまま公開中）

- H-51「Preview から正式版への流れ」との住み分け：H-51 はプレビュー→GA の**段階の定義と手順**（SLA 対象外である点、業務適用の判断基準）を扱う「手順・判断材料」のページ。本エントリ H-61 は「なぜこの業界はプレビューを多用するのか」という**文化・背景**と、読者が体感する現れ方（名前が変わる・機能が消える・無料で試せる）に絞る。段階名や GA の定義は H-51 に譲り、本エントリでは再定義しない。
