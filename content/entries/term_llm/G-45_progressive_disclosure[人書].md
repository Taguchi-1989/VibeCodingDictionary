# 段階的開示

## tagline

情報を「見出し→本体→参照ファイル」の三段階で必要な分だけ開く設計です。

<!-- ━━━━━━━━ 左ページ ━━━━━━━━ -->

## 何をしてくれるか

必要になった分だけ情報を渡し、Context（コンテキスト）を圧迫しない考え方です。まず見出しだけを見せ、使うと決まったら本体を、さらに深掘りしたいときは参照ファイルを開かせます。

## どこで出会うか

Agent Skills（エージェントスキルズ）が採る仕組みです。SKILL.md は見出しだけで数百トークンに収まり、使うと決まった時だけ本体が読み込まれます。CLAUDE.md や README にも同じ発想が生きています。

## メイン図

### 図の狙い

「見出し→本体→参照ファイル」の三段の扉を、開く順番と一緒に示す。全部を一度に開かない理由が Context の余白として見えるようにする。

### C. 概念図（figure_type: structure）

- 中心に置く概念: Claude（読者からの依頼を受けて判断する役）
- 周辺の要素: 第一の扉「見出しだけ」（数十〜百トークン）／第二の扉「本体」（使うと決めてから開く）／第三の扉「参照ファイル」（さらに知りたいときだけ開く）
- 関係の描き方: 3 枚の扉を横に並べ、開くほど内側の情報が増える階段状に。扉の外側に「Context の余白」を点線で添える

## 会話での使い方例

「段階的開示のおかげで SKILL.md は薄くて Context を圧迫しませんよね。」

<!-- ━━━━━━━━ 右ページ ━━━━━━━━ -->

## この用語の見どころ

### 1. 役割

必要になった分だけ情報を読み込ませる設計思想です。

### 2. うれしさ

Context を圧迫せず、スキルを増やしても負担が増えません。

### 3. 注意点

見出しが曖昧だと、必要な場面で呼ばれないことがあります。

### 4. どこで役立つか

Skill や CLAUDE.md の中身を設計する場面で効きます。

### 5. はじめに

「見出し→本体→参照ファイル」という三段構えの存在です。

### 6. 深掘り先

SKILL.md、CLAUDE.md、Context Window

## 開発フローでの位置（必須）

1. 見出しを書く — スキル名と使う場面をひとことで表す
2. 本体を分離する — 手順の詳細を別ファイルの本体に書く
3. 参照ファイルを添える — さらに深い情報を別ファイルへ逃がす
4. Claude が判断する — 会話の流れから必要な段階だけ読み込む
5. 肥大化を見直す — 本体が膨らんだら参照ファイルへ移す

## 誌面ポンチ絵メモ

### メイン図（左ページ中段 / figure_type: structure）

- 描く内容: 横並びの 3 枚の扉。第一の扉は薄く小さく「見出しだけ」のタグ、第二の扉は少し厚い「本体」の文書、第三の扉は棚のような「参照ファイル」の束。扉を開くほど情報量が増える階段状に配置し、外側に Context の余白を点線で囲む
- 登場人物: Claude を擬人化したキャラクターが手前に立ち、まず第一の扉だけを覗き込んでいる
- 吹き出し・心の声: 「まずは見出しだけ確認」「これ使うから本体を開こう」「もっと知りたいから参照ファイルへ」
- 中央に置くキーワード/ラベル: 段階的開示 ＝ 必要な分だけ、順番に開く

### 6 視点アイコン（右ページ上段）

- 共通アイコン流用（個別演出が要るときだけ書き足す）

### 開発フロー図（右ページ下段）

- Step 1 のアイコン/絵柄: タグに短い見出しを書く人
- Step 2 のアイコン/絵柄: 本体の文書を別ファイルにまとめる人
- Step 3 のアイコン/絵柄: 棚に参照ファイルを並べる人
- Step 4 のアイコン/絵柄: Claude が会話を読んで扉を選ぶアイコン
- Step 5 のアイコン/絵柄: 膨らんだ本体をハサミで整理する人


## コミュニティ補完メモ

- SKILL.md（G-22）との住み分け：SKILL.md は段階的開示を実装した具体的なファイル形式。本エントリは「なぜあの三段構えなのか」という設計思想そのものを扱う。
- CLAUDE.md（G-20）との住み分け：CLAUDE.md はセッション開始時に常時読まれる記憶ファイルで、段階的開示の対象外に近い（全文が毎回読まれる）。ただし「入口を短く、詳細はリンク先へ」という書き方の指針として同じ発想が効く点を「どこで出会うか」で触れる。
- Context（G-1）／Context Window（G-5）との住み分け：段階的開示が解決しようとしている問題（Context の圧迫）はそちらのエントリで詳しく扱う。本エントリは解決の考え方に絞る。
- Auto-compact（G-47）との住み分け：Auto-compact は膨らんだ後に圧縮する事後対応。段階的開示は膨らませない事前設計。両者は対になる関係として扱い、深掘りはしない。
