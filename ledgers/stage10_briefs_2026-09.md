# Stage 10 ブリーフ（2026-09-05）— J-127 決定論と非決定論

*著者の指示（2026-09-05）で追加します。「実運用は決定論に寄せていくのではないか」という著者の見立てが、世の中でどう議論されているかを確認したうえで書きます。事実はすべて 2026-09-05 に web で確認しました。*

## この語を立てる理由

- 本書には「LLM は同じ入力でも同じ出力になるとは限らない」という前提が各所に散っていますが、**その性質自体を正面から扱うエントリがありません**
- 巻末付録 03（導入ステップ別やることマップ）で「運用のたびに影響評価を回す」と書いていますが、**運用時に LLM を呼ばない設計なら話が変わります**。その分岐を語として持たせる必要があります
- 著者は機能安全の実務者で、「最終的には決定論に寄せる」という見立てを持っています。**この見立ては 2026 年時点で実在の議論であり、名前もついています**

## 押さえる事実

### 1. 温度 0 にしても再現しない（ここが出発点）

- Thinking Machines Lab が 2025 年 9 月に公表した実測: **同じプロンプトを温度 0 で 1,000 回流したところ、80 種類の異なる出力**になった
- 原因は、よく言われる浮動小数の非結合性ではなく、**バッチサイズの揺れ**。本番では同時リクエスト数でバッチが動的に変わり、matmul・RMSNorm・attention の数値がサンプル単位で変わる
- バッチ不変なカーネルに差し替えたところ、**1,000 回すべてビット単位で一致**（Qwen3-8B / vLLM で実証）
- **つまり「温度 0 ＝ 決定論」ではありません。** 技術的には潰せますが、既定では潰れていません
- 出典: https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/ ／ https://simonwillison.net/2025/Sep/11/defeating-nondeterminism/

### 2. 「実行ループから LLM を外す」という設計には名前がついている

- **Compiled AI**（arXiv:2604.05150、2026 年 4 月）。LLM を**コンパイル時に 1 回だけ**呼んで実行可能なコードを生成し、以後はモデルを呼ばずに決定論的に実行する考え方
- 3 つの性質: 生成時の 1 回だけの LLM 呼び出し／トークン消費ゼロの決定論実行／**多段の検証を必須にする**（セキュリティ・構文・実行・精度の各チェックを通ってから配備）
- 報告されている効果: 1,000 トランザクションで **トークン 57 倍削減**、**再現性 100%**（ランタイム推論は 95%）、月 100 万トランザクションで TCO が **40〜57 倍削減**
- **プロンプトインジェクションの攻撃面が縮む**: 「1 トランザクションに 1 回の LLM 呼び出し」から「ワークフロー種別ごとに 1 回」へ
- **著者自身が万能薬ではないと言っています**: 構造化された予測可能な入力には compiled、ノイズの多い開放的な内容にはランタイム推論、混在する本番系では信頼度に応じて LLM にフォールバックするハイブリッド、という使い分けを推奨
- 出典: https://www.alphaxiv.org/overview/2604.05150v1 ／ https://arxiv.org/html/2604.05150v1 ／ https://www.xy.ai/tech-behind-xyai/compiled-ai-deterministic-code-generation

### 3. 日本語圏でも同じ問いが議論されている

- 日経クロステックが 2026-05-29 に「**LLM にどこまで委ねるか、AI エージェントの『非決定論』問題**」を掲載
- 業務の性質を決定論的（確実性が要る）／非決定論的（柔軟性が要る）に分けてプロダクト設計を変える、という整理も出ています
- 出典: https://xtech.nikkei.com/atcl/nxt/column/18/00692/052800189/ ／ https://note.com/gentle_ixora532/n/n9c755cdca3a9

### 4. 規格・本書の他エントリとのつながり（本書独自の整理として書く）

- 実行時に LLM を呼ばなければ、**モデルのドリフト監視は不要になり、8.4（影響評価を運用で回す）の継続的な負担が出荷前の 1 回に寄せられます**
- ただし**リスクは消えず移動します**。同じ要求から毎回違うコードが出るので、非決定性は開発時に移り、検証で担保する話になります（Compiled AI が多段検証を必須にしているのはこのためです）
- また、決定論にすると**入力や環境が変わっても同じ答えを返し続けます**。モデルのドリフトは消えますが、前提のずれに気づけなくなる面があります

## 書き方の指示

- **「決定論に寄せれば安全」と書かないでください。** リスクが消えるのではなく、扱いやすい形（開発時の検証）に移る、という書き方にします
- 温度 0 の実測（1,000 回で 80 種類）は誌面に入れてください。非エンジニア読者にいちばん効く事実です
- 数字は出典のあるものだけ。**57 倍・40〜57 倍・100% / 95% は 1 つの論文の報告値**なので、断定せず「〜と報告されています」の形にしてください
- **書かないこと**: どちらの設計が優れているかの断定／将来こうなるという予測（著者の見立ては著者欄に入るので、本文では扱わない）／実務者調査の割合（検索結果に出た数字は出典の帰属が確認できていないため使わない）
