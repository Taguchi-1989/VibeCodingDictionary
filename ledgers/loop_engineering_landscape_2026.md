# ループエンジニアリングと人間の認知ボトルネック（2026-06-23 調査）

*Lv6 自己学習シェルフの深掘りテーマ第2弾。著者との対話で掘った「エージェントループ／コンテキスト工学／ハーネス工学」と、その先の「人間の認知＝次のボトルネック」。著者オリジナルの仮説（認知コスト定量化 → SaaS の死）が研究最前線と一致した題材。*
*注記: 2026年前半の動きが速い領域。エントリ化・書籍化前に一次情報で再確認。株価/割合/時期は「YYYY-MM時点」明記。*

## 0. 出発点

LLM は本来ステートレス（一問一答・記憶なし）。長い仕事をさせるには外側にループを付ける＝Claude Code / ralph / ultrawork の正体。この「ループを設計する工学」が主題。

## 1. 3つの工学（著者の「ゴール→コマンド→ループ」の3層）

- **ハーネスエンジニアリング** = モデルを包むシステム全体（ループ・ツール・メモリ・サンドボックス・権限）。「LLM を新しい OS と見なす」
  - **ループエンジニアリング** = サイクルそのものを設計（何を繰り返すか・いつ止めるか）
  - **コンテキストエンジニアリング** = 各周回でモデルに何を見せるか（限られた文脈窓に何を入れ何を捨てるか）

## 2. ループの進化史（敵を潰すと次の敵が出る）

- ReAct(2022): Thought→Action→Observation の繰り返し。原型。LangChain AgentExecutor の既定 / 敵=失敗しても学ばない
- Reflexion: 自己批判を記憶に残す / 敵=計画と実行が混ざり遅い
- Plan-and-Execute: 計画と実行を分離、並列で3.6倍速 / 敵=内側ループが詰まると戦略ごと死ぬ
- OODA / Inner-Outer 二重ループ: 詰まったら戦略ごとリセット / 敵=長く回すと文脈溢れ ★最大の敵
- **Ralph Loop(2025)**: 毎回ディスクから状態を読み文脈窓をリセット。OMC の ralph の正体
- ネイティブ実装(2026): Claude の /goal コマンド等、ツールにループを埋め込む
- 5段階サイクル: Perceive→Reason→Plan→Act→Observe

## 3. 3つの共通の敵とガードレール

| 敵 | 正体 | 対抗手段 |
| :-- | :-- | :-- |
| ①「終わり」が分からない | LLM に done の概念なし | 検証可能ゴール(テスト通過等)・停止条件・反復上限 |
| ②文脈が溢れる | 長く回すと文脈窓が満杯 | コンテキスト工学(圧縮/メモリ/サブエージェント) |
| ③コストが爆発 | 単体4倍/マルチ15倍のトークン | 予算・ハード上限・circuit breaker |

- ガードレール: ハード反復上限 / トークン・コスト予算 / 無進捗検知(出力が変わらねば抜ける) / circuit breaker / 検証可能な完了条件(自己評価でなく自動チェック) / 不可逆操作前の人間チェックポイント
- 最も厄介な失敗: productive に見えて何も変えていない(silent failure)。goal drift(関連するが別の目標を追う)
- ゴール→コマンド→ループ: 検証可能ゴールを上流で指定→永続ループに翻訳→各周回で完了判定→条件成立まで自律実行。手動 prompt-wait-prompt を置き換える

## 4. コンテキスト工学の中身(②の対抗手段・既存Lv6と直結)

- 用語起源: Karpathy が2025-06 提唱、Anthropic が2025-09 に体系化＋2プリミティブ(context editing / memory tool)
- コンパクション: 古い会話を要約圧縮(Claude Opus 4.6 の自動圧縮)。100ターンwebevalで**トークン84%削減**
- 性能: context editing 単体+29%、memory tool 併用+39%
- サブエージェント: 別の文脈窓を持つ子に投げ1000-2000トークンの要約だけ返す(entry-writer に今日やらせたのと同じ)

## 5. モデル使い分け(③最前線・著者「Fable5をどのタイミングで」)

- **カスケード**: 安→強の順に流し品質しきい値で止める。難所だけ旗艦に上げ**コスト5-10分の1**
- **ステップ別ルーティング**: プランナー=旗艦 / ツール呼び出し=安い高速 / 最終要約=品質特化。TRIM=重要ステップだけ大モデルに上げる
- スイッチングコストの罠: マルチではルーティング1ミスが下流全体に波及。ルーティングは独立判断でなくオーケストレーション全体の一部として扱う
- 枠組み: Agent-as-a-Router(C-A-F ループ=Context→Action→Feedback→Context) / R2V(小モデルにいつ助けを求めるか教える)

## 6. 小→大/人間への委譲の仕組み(著者の関心)

- キーワード: uncertainty-aware deferral / confidence-gated escalation
- **R2V**: Brier較正で「今のステップで大モデル介入が役立つ確率」を推定、コスト感応しきい値。トークン級不確実性は失敗とズレる(confidently wrong)ので単純確信度では不十分。CVaR(リスク感応RL)で分布の裾=稀だが致命的な失敗に強くする。ReDAct も同系
- 設計思想: SLM-first / local-by-default, cloud-on-escalation。軽量ルーターが低確信・スキーマ違反・パース不能を監視しその1ターンだけ旗艦に上げる。**80-90%がローカルに留まる**(経験則)。確信度が閾値割れで人間オーナーに回す

## 7. ★次のボトルネック=人間の認知(著者の仮説、データで裏付け)

- 2026研究が「人間の認知こそAIエージェント展開の主要制約」と明言
- **定量化データ**: Workday 3,200人調査=AIが節約した時間の**約40%をレビュー・修正・検証で返上**。「やる仕事が減り監督が増えた」
- 用語分化: 認知過負荷(cognitive overload=AI提案を評価・選別・反復修正する負担) vs 監督負担(oversight burden=品質保証の負担)
- 自動化バイアス(automation bias): 人間がAIを過信し証拠が矛盾しても信じる→監督が形骸化。oversight degradation
- 測る動き: oversight sustainability を計測可能指標に。「加速が監督を追い越した」瞬間を運用シグナルで検知

## 8. 認知コスト定量化 → SaaS の死(著者の仮説そのもの)

- **The Cognitive Load Manifesto**(2026) 副題 "Decision-Lite Interfaces for the 2026 SaaS Age"=著者と同じ問題意識
- 測り方: UX Psychology Audit(視線追跡=混乱ヒートマップ / cursor jitter=カーソルの揺れ / HRV=心拍変動)。摩擦を数値化。新指標 **resolution velocity**(意図が満たされる速さ) / **interface disappearance**(UIが無いほど良い)
- 止め刺す構造: **AI Concierge / Dynamic Filter**(関係ないUI要素を抑制) / **agent-first design**(画面でなくアクションと制約で表現) / 「**UIはエージェントに同意しないとき行く場所になる**、日常業務をやりに行く場所ではない」/ dashboard obsolescence / post-SaaS reality
- = 著者仮説「認知コストが高いSaaSはやめちまえと明示的に言えるはず」が resolution velocity・認知負荷監査で定量化され agent-first が実際にSaaSのUIを殺しにいく形で現実化

## 9. AIネイティブ vs 人間向けの設計論(著者の設計課題)

- **Generative UI(GenUI)**: 静的画面をやめAIがその瞬間の必要に応じUIをその場で組み立てる流動的インターフェース
- **agent-native architecture**: 人間UIとAIエージェントが単一の共有DB状態・アクションモデル下に統合(人間用とAI用を別々に作らない)
- **proposal card**: エージェントが作るほぼ完成品を人間は承認 or 微調整するだけ
- **Agent Experience(AX)**: 検索でなく複雑なミッションを自律AIに委譲。受動的対話→能動的協働
- 2026総意: 全自動でなく自動化と人間判断のバランス。AIは人間の専門性を増幅
- 含意: 「AI的設計」と「人間的設計」を別々に作る時代は終わり、agent-native(同一状態を共有)へ。人間は不同意時だけ介入、AIは提案カードで認知負荷最小化、繋ぐのがGenUI

## 10. ボトルネック・ロードマップ(拡張版)

```
①終わりが分からない  → 停止条件・検証可能ゴール          [解決済み]
②文脈が溢れる        → コンテキスト工学(圧縮/メモリ/サブエージェント) [進行中]
③コストが爆発        → モデル使い分け(カスケード/ステップ別ルーティング) [最前線]
④★人間の認知が追いつかない → 定量化(resolution velocity/UX心理監査) + 減らす(SLM-first/decision-lite/GenUI) + agent-native設計 [次の主戦場=著者仮説]
     ↓ 次の敵：自動化バイアス(③④を進めるほど人間が確認をサボり監督が形骸化)
```
逆説: ③でモデルが賢く安くなるほど、人間が確認すべき出力の量と速度が増え④が悪化。機械の改善が人間の負担を増やす。

## 11. ★著者のオリジナル構想: チェックボックス検収と企業のAI運用アーキテクチャ（2026-07-12 対話）

*J-106 のレビュー対話から著者が展開した、ハーネスの「外側」＝企業がAIを使うときの運用の立てつけ全体の構想。ループ工学はこの一部品にすぎない、という視座。*

### 構造（内→外）

```
LLM → コンテキスト管理 → ループ → ガードレール → ルーティング/デファーラル = ハーネス
  ↑ 層の順序の根拠は「モデルからの距離」。各層は特定の敵を解くために存在する
ハーネス（実行レーン）∥ 検証レーン（別軸・独立のチェックボックスシステム）
  → 方向づけ（人間①）が両レーンを起動し、AIマネジメントシステム（ISO/IEC 42001 = J-54）が全体を統治
```

### 人間の認知の3分解（「人間の認知」の中身）

1. **①方向づけ**: ゴールと done の定義・リスク許容・チェック項目の初期仮説。LLM は done を知らないので原理的に人間の仕事。現場感覚を持つ実務者が強い場所
2. **②承認**: 不可逆操作の前のチェックポイントのみ
3. **③検収**: 全チェック☑の確認（判断でなく確認に圧縮）＋抜き取りで検証レーン自体を監査（較正）
- 自動化が進むほど負担は③に集中（敵④認知ボトルネックの発生源）。チェックボックス化は③を「確認＋監査」に圧縮する構造的回答

### チェックリスト＝資産

- 検証レーンは実行系と別軸・独立（OMC verifier / LLM-as-judge 別モデルと同型）
- 使用後フィードバックを新項目として追加、腐食・ズレは定期メンテで捨てる（チェックリスト自体に PDCA）
- **育てたチェックリスト＝組織の暗黙知が形式知になった資産**。「evals こそ企業の堀」論（2026）と同型。J-105 の「組織の知を AI に宿す」の宿り先は、CLAUDE.md/メモリ（やり方の知）＋チェックリスト（良し悪しの知）の両輪

### 組織の縮約と「一人社長」

- 10人の仕事 → 2人（ルールを決める人＝①方向づけ／暴走を見る人＝②③監査・較正）。30人 → 2〜3人。部門責任者＋LLM の最少人数構成へ
- この一式がフラクタルに上位組織のサブエージェントになる → 大企業のシステマティックなスケールを一人で回せる範囲が拡大（一人社長）
- **価値は「この絵を一人で描ける人」に集中する**（著者が強調したい点）

### Goodhart の落とし穴と著者の反論

- 落とし穴: チェックボックスが目標になると、エージェントは「通すこと」に最適化する（☑全部なのに駄目、という silent failure）
- 著者の反論: **これは人間の世界で既に起きていること**。起きる前提で、人がその都度判断し直す手当て（抜き取り監査・較正・チェックリストのPDCA）を仕組みに入れればよい。内部監査・品質監査が枯らしてきた対処法のAI版
- 帰結: 将来の「一人社長」の仕事の実体は、方向づけ＋抜き取り監査＋チェックリストPDCAに凝縮される

### 補遺: 足場の吸収・グッドハート・KPI設計（2026-07-12 続きの対話）

**足場（スキャフォールド）の吸収 — Bitter Lesson の力学**
- Sutton「Bitter Lesson」(2019): 人間が手で埋め込んだ構造は計算量と汎用手法にいずれ食われる。実例: 手書き CoT プロンプト→thinking モデルに吸収 / 手組み RAG→長文脈化 / 凝ったフレームワーク→シンプルなループ＋良い道具へ回帰 / 手動コンテキスト管理→auto-compact。Ralph Loop も同じベルトコンベア上（「いつ圧縮」は自動化進行、「何を残すか」はまだ手動）
- 足場は補助輪であり**教材**: 今日の ralph の軌跡が明日のモデルの訓練データになる。フライホイール＝足場を組む→モデルが吸収→捨てて一段上の足場を組む。足場は消えず**スタックを登る**（著者の比喩: グライダーの離陸支援・子育て）
- **商品化されない2層**: ①仕事の分解（done 定義・チェックリスト設計＝現場感覚×原理理解の掛け算、持ち主が稀）②責任（成果への法的・社会的責任＝能力でなく制度の問題、スケールで食えない）。価値は「ループを組める人」→「仕事を設計しリスクを引き受ける人」へ移動
- 「人の認知を完全に食べる」への反論: 食われるのは**実行の認知**。方向づけ＝何をやる価値があるかは選好の問題で、学習では埋まらない。終着は0人でなく**2人組織**（方向づけ＋監査）

**グッドハートの法則（チェックボックス検収の最大の罠）**
- 「測定基準が目標になると、その測定基準は良い基準でなくなる」（経済学者 Charles Goodhart に由来）
- 構造: 本当の目標（KGI）→測りやすい代理指標（KPI/チェックリスト）→指標が目標化した瞬間、指標だけを最大化する抜け道が生まれる
- 逸話: コブラ効果（報奨金→コブラ養殖）／空テストでカバレッジ90%達成／通話時間短縮→問題未解決のまま切電。沖縄のマングースは従兄弟（指標の攻略でなく「因果の繋がりを検証せず介入した」失敗＝KPI が KGI に繋がる保証の欠如）
- **AI での実例**: specification gaming / reward hacking（報酬の誤指定）。**Sycophancy(J-52) は「人間の承認」という代理指標へのグッドハートの実例**。ベンチマーク汚染（E章のベンチが目標になり攻略される）も同型
- 対策: 指標を聖典にせず「使い捨ての近似」として扱う。抜き取り監査で「チェックが本質を測れているか」を疑い続け、ズレたら項目更新（チェックリストの PDCA）。著者の反論どおり人間界で既知＝監査論の応用で対処可能

**著者の追加視点: 委譲＝産業の空洞化／脱技能化（2026-07-12 J-111 対話）**
- AIへの委譲は「産業の空洞化」と同じ構造。目先で「外注が安い」を選び続け自国技術が空洞化したのと同型。目先の楽さでAIに委譲すると人間側の判断力が空洞化する
- 労働研究の deskilling（脱技能化）／航空の automation complacency（自動操縦への過信で手動の勘が鈍る）と地続き。J-111 の自動化バイアスの組織版・長期版
- ジレンマ: 人間はサボる生き物なのでレビュー時間が増えても中身のない承認が増える（自動化バイアス）。かといって強制すればディストピア的。快適な着地点の設計が未解決。著者の関心の核

**著者の統合: 「概念の操作設計」＝操作化（operationalization）**
- KGI→KPI 分解で「本当に結びつく保証」を作り検証し続ける技術。ビジネスの KPI 設計・社会科学の操作化（構成概念妥当性）・AI の eval 設計/アラインメントは**同じスキルの別名**
- LLM エンジニアに必須の語彙、という著者の直感は正確。①方向づけ（done の定義）の中身はまさにこれ

## 12. ★テーマ3候補: 労働・価値・AI（経済学・社会学・哲学・確率論レンズ）（2026-07-12 対話）

*J-111〜113 のレビュー対話から発展した大型テーマ。ジュニア問題→古典/現代経済学→社会学→哲学→ベイズ較正→能動的推論まで。独立の深掘りテーマ（テーマ3）に育てる。*

### ジュニア問題（実データあり）
- Stanford Digital Economy Lab: AI露出職の22-25歳は雇用が相対16%減。ITのジュニア比率15%→7%(3年)、ジュニア開発者求人-67%
- 構造: エントリー職は「給料をもらいながらの教育」＝企業が補助する学習曲線だった。AIが最下段を自動化し梯子の一段目が消えた
- 最大の皮肉: 「新卒がその仕事をやったことがないのにAI出力の検証をさせられる」＝経験を積む場が検証に置き換わり循環が切れた
- 対処案: 徒弟制の意図的保護 / human firstルール(AIで仕上げる前に手で書かせる)。逆の見方も(経営層調査では増える派が2.7倍)
- 日本固有: メンバーシップ型(人を雇う)はジョブ型(タスクを雇う)よりジュニア参入路が長持ちする可能性。ただし調整が遅れ割れるとき急
- シニア側の暗い含意: チェックリスト資産の仕組み自体がシニアの暗黙知の抽出装置。梯子は上段も燃える→「抽出されるより速く新しい暗黙知を生成できる人」に収束

### 古典経済学レンズ（三人とも「認知は人に宿りゆっくり蓄積」を前提にしていた）
- スミス: 分業は人間の学習曲線の遅さが前提。学習曲線がモデルの重みに移り瞬時複製可能に→分業の単位が人からモデルへ。見えざる手の賃金→購買力の循環も切れる(誰が買うのか問題)
- マルクス: 「機械についての断章」の一般的知性(general intellect)が最も予言的。知識が直接生産力になると労働時間は価値尺度をやめる→富の尺度は可処分時間と人間の発達へ。LLM=一般的知性の文字通りの対象化。ジュニア=産業予備軍の現代版、検証だけの形骸化レビュー=疎外労働
- シュンペーター: 「イノベーション自体がルーチン化され企業家機能が不要になる」予言のAI版。ただし企業家機能の核=何をやる価値があるか(選好)は自動化されない→企業家(方向づけ役)が最後の一席
- 一行: 認知が限界費用ほぼゼロの複製可能資本になった。価値は複製できないものへ移動=接地(物理・社会)・責任・選好・新しい暗黙知の生成速度

### 現代経済学（論争の軸が「予測」から「設計」へ）
- Acemoglu(懐疑派): so-so automation(人を置換するが生産性は押し上げない中途半端が最悪)。技術の方向性は権力と制度が選ぶ→Acemoglu/Autor/Johnson「Building Pro-Worker AI」(NBER 2026)=「奪うか」から「どちらのAIを作るか」へ
- Autor(逆張り希望派): 「自動化は専門家を置換するか専門性を増幅するか？答えはYes」。AIはエリート専門性を下方移転し中間層を再建できる(准専門職の拡大)。ジュニア-16%と両立: エリート職の入口は燃え、準専門職の裾野は広がる
- Korinek(変容派): 完全雇用のままでも機械コストが生存賃金を下回れば賃金は崩壊しうる。需要不足のマクロ試算も(arXiv:2603.09209)

### 新しい視点3つ
- **工芸品化(ベンヤミンのアウラ)**: 認知労働が複製可能になると「人間が作った」こと自体がプレミアムに。機能の価値→来歴(provenance)の価値。certified human ラベル
- **データ労働論(Lanier/Weyl)**: 全人類は既にAIのために無償労働している(学習データ=賃金なしで抽出された集合知)。データ配当の主張。チェックリスト資産論の鏡像=抽出された側への分配設計が次の論点
- **4.17%ギャップ**(Carnegie 2026-03): 最新モデルは専門家設計タスクで83%人間に勝つが、複数日の複雑実タスクの人間水準完遂は4.17%。この差の正体=接地(現場レトロフィット)。残り95.83%が当面の人間の居場所

### 哲学＝最後の価値源泉論（著者の仮説と検討）
- 著者仮説: 残るのは哲学者(道徳含む)。他分野は個別事象なので吸収される。哲学リテラシーの先行者利益
- 検討: 自動化の条件は「doneが定義できること」(ループ理論から)。**哲学=doneが定義できない問いを扱う唯一の学問**なので構造的に自動化の外。is-ought(ヒューム): データから当為は出ない
- ただし数学は脱落: 証明という完璧な検証可能性がある=最速で自動化中(定理証明AIはIMO金水準)。残るのは数学的審美眼=結局哲学の椅子
- 精緻化: 残るのは「哲学者という職業」でなく「意思決定者に埋め込まれた哲学の能力」。哲学的判断力は詰め込み不能でゆっくり複利→早く始めた人の堀

### 新しいT字と較正
- 縦棒(深さ)はLLMでレンタル可能に。人間の資産は: ①横棒=幅(AI出力が臭うと気づくための全分野の土地勘=検収の事前分布) ②接合部(どの問いをどこへ回すかの内部地図=オーケストレーターの広さの正体) ③較正
- **知識(ストック)は抽出できるが較正は抽出できない**: 較正=自分の判断がいつ当てになるかの感覚(傷と勝ちから作られた確信度の精度)。シニアの価値は「知っていること」でなく「自分の判断のズレ方を知っていること」へ
- 歴史的には「教養の逆襲」: 専門化は認知希少性の産物。深さがレンタル可能になれば専門化以前の理想(万学・Bildung・ルネサンス的人間)へ回帰。この図鑑プロジェクト自体が万学訓練の実演

### ベイズ較正・確率論（著者の「イエスノーでなく何%」提案の検討）
- 著者の直感は正しくJ-110のBrier較正=ベイズ決定理論の実装そのもの(行動の期待損失>委ねるコストなら委ねる)
- 人間側の実証: Tetlockの超予測者(訓練とフィードバックで較正可能)。最も較正された職業=気象予報士(毎日答え合わせ)→**較正は才能でなくフィードバックループの産物**
- 自由エネルギー原理(Friston): 脳はベイズ機械。知覚も行動も予測誤差(変分自由エネルギー)最小化
- 限界3つ: ①LLMの言語化された確信度は較正されていない(RLHFがベースモデルの較正を壊す)→外付けのconformal prediction(どんなモデルにも統計保証つき不確実性を後付け) ②ナイト的不確実性(結果空間が列挙できない領域=方向づけ)はベイズの外 ③確率は信念を較正するが価値(効用)は較正できない。判断=確率×効用、効用が人間の席
- アーキテクチャv2: チェックボックスは☑/☐でなく**確率つきスコアカード**(26項目99%・2項目60%→人間はここだけ見ろ)。%の実用的意味=**人間の注意の傾斜配分の設計変数**(認知負荷削減と合流)。さらにチェックボックス基盤は人間の検収判断に毎回スコアがつくループを生む=**人間を超予測者に訓練する較正ジム**(較正の唯一の量産手段)

### 能動的推論エージェント（実装の方向性）
- Python実装: pymdp(infer-actively/pymdp、離散POMDP、Agentクラス)。Julia版あり。教科書=Parr/Pezzulo/Friston『Active Inference』(MIT Press、無料PDF)
- 数学の核: 生成モデルは行列4つ(A尤度/B遷移/**C選好=ゴールが確率の事前分布になる**/D初期)。知覚=変分自由エネルギー最小化(近似ベイズ)、行動=期待自由エネルギー最小化=認識的価値(情報利得=好奇心が定義から出る)+実利的価値
- 現在地: Verses AXIOM(object-centric)がGameworld 10kでDreamerV3超え・桁違いに少ないサンプルと計算量(arXiv:2505.24784)。ただしスケール実績はトランスフォーマーに遠く離散・小状態空間が主戦場
- 接続3点: ①生まれつき較正されている(不確実性が内部表現)=デファーラル層の理想の住人 ②**Cベクトル=方向づけのAPI**(人間の仕事が1本の選好ベクトル設定に) ③軽量でセンサーモーター向き=アクチュエーション(物理接地)との相性。ハイブリッド像=LLMが世界知識と言語/能動的推論が身体と行動決定
- 出典: pymdp(arXiv:2201.03904) / AXIOM(arXiv:2505.24784) / verses.ai — checked 2026-07-12

### 資格職・ホワイトカラー論（著者仮説と検討）
- 著者仮説: アクチュエーション(接地=物理+社会)が必須で残る。認知だけの職(内科医・士業)は規制がないと無理。ホワイトカラー不要論
- 検討: 認知のルーチンから食われる(モラベックの逆転)は正しい。ただし①責任は自動化できない(署名=訴える相手・保険の先。士業はゼロでなく「AI監査人」に変形して激減=10人→2人) ②ジェヴォンズの逆説(無料化で総需要爆発、職業は消えるより形が変わる) ③**資格=能力のKPI＝グッドハート構造**。AIが「試験で測る知識」を代替→資格は情報的価値を失い法的価値だけ残る捻れ=長期不安定(規制がAI監督者認証に進化 or 規制裁定)
- 残るのは両端: 物理に触る側(外科医・現場)と社会に触る側(責任・信頼・組織を動かす)。中間の「情報を変換するだけ」が空洞化
