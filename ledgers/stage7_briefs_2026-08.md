## H — 進め方

### H-2 ペアプログラミング

- **位置づけ**：**AI との開発が「これに近い」と説明される元ネタ**。人間同士のやり方を知ると、AI との付き合い方の見通しが立つ
- **押さえる事実**：2 人が 1 台の画面を共有して一緒に書く進め方で、アジャイル開発の実践として広まった／手を動かす側（ドライバー）と、方針を見る側（ナビゲーター）に分かれ、役割を交代しながら進める／利点は、その場でレビューされること、知識が伝わること、詰まったときに抜け出しやすいこと／欠点は、2 人分の時間を使うこと、相性や集中の問題／AI との開発は「AI がドライバー、人がナビゲーター」と説明されることが多く、この語を知っていると役割分担の話がしやすい
- **出典**：Martin Fowler「On Pair Programming」<https://martinfowler.com/articles/on-pair-programming.html>
- **書かないこと**：バイブコーディングの進め方（H-3）、コードレビュー（H-4）
- 目安 reader_level 1-2 / importance B / figure_type structure

### H-3 バイブコーディングの流儀

- **位置づけ**：G-40「バイブコーディング（用語）」の実践編。**この本の中核に近い 1 本**。用語の定義でも歴史でもなく「どう進めるか」
- **押さえる事実**：作りたいものを言葉で伝え、AI に手を動かしてもらい、出てきたものを見て次を頼む、という往復で進める／うまくいく型として、(1) 小さく頼んで動くところまで確かめる、(2) 動いたら区切りを記録する（コミット）、(3) 直したいところを具体的に伝える、(4) 方針が変わったら前の状態に戻す、という流れがよく挙げられる／丸投げすると壊れたときに戻せなくなるため、**戻れる状態を保つこと**が実務上のいちばんの勘所／読めなくても動けばよい場面と、読めないと困る場面（お金・個人情報・公開範囲）を分けて考える
- **出典**：Andrej Karpathy の投稿（2025-02-02）<https://x.com/karpathy/status/1886192184808149383>、Anthropic「Claude Code best practices」<https://www.anthropic.com/engineering/claude-code-best-practices>
- **書かないこと**：語の定義（G-40）、命名の経緯（H-63）、エージェントの定義（G-49）

- **出典**：GitHub Docs「プルリクエストのレビュー」<https://docs.github.com/ja/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests>、Google「Code Review Developer Guide」<https://google.github.io/eng-practices/review/>

## I — MCP

- **位置づけ**：I-1〜5 で仕組みを知った読者が「自分でも作れるのか」と思ったときの入口。**作る側**の話

- **出典**：Model Context Protocol 公式 <https://modelcontextprotocol.io/>、公式 SDK <https://github.com/modelcontextprotocol>
- **書かないこと**：MCP の概念（I-1）、Server の一般説明（I-2）、登録・設定の手順（I-81）

### I-81 MCP の登録・設定

- **位置づけ**：I-80 が「作る」なら、こちらは**使えるようにする**手続き。読者がいちばんつまずく実務
- **押さえる事実**：作った、あるいは配布されている MCP サーバーは、**使う側のツールに登録して初めて使える**／Claude Desktop では設定画面から `claude_desktop_config.json` を開いて書き、アプリを再起動する／Claude Code では `claude mcp add` のようなコマンドで登録でき、`claude mcp list` で一覧を確認できる／登録する範囲（スコープ）を選べて、自分の PC だけ／このプロジェクトだけ（`.mcp.json` を置いてチームで共有）／自分のユーザー全体、といった使い分けがある／API キーなどの秘密はここで渡すことになるので、設定ファイルの扱いは F-214 の注意がそのまま当てはまる
- **出典**：Claude Code Docs「MCP」<https://code.claude.com/docs/ja/mcp>、Model Context Protocol 公式 <https://modelcontextprotocol.io/>

## J — 一般 AI・テック語彙

### J-22 パラメータ数の単位

- **位置づけ**：「7B」「70B」といった表記が読めるようになる 1 本。ニュースでもモデル名でも毎日見る
- **押さえる事実**：パラメータはモデルの中で学習によって決まる数値のことで、その個数がモデルの規模の目安になる／表記は **B＝Billion（10 億）、M＝Million（100 万）、T＝Trillion（1 兆）**／「Llama 3 8B」なら約 80 億個、「70B」なら約 700 億個という読み方／手元で動かせるかの目安になり、ごく大まかには「B の数 × 2GB 程度のメモリが要る」と語られることが多い（量子化すればもっと小さくできる。J-19）／大きいほど賢いとは限らず、学習データや手法でも変わる／商用の大手モデルはパラメータ数を公表しないことが多い
- **出典**：Hugging Face のモデルカード規約 <https://huggingface.co/docs/hub/model-cards>
- **書かないこと**：量子化の仕組み（J-19）、スケーリング則（J-35）

### J-32 ノイマン型

- **位置づけ**：J-31 第 5 世代コンピュータ・J-33 量子コンピュータと並ぶ古典枠。**今のコンピュータの基本設計**であり、GPU や NPU の話の前提にもなる
- **押さえる事実**：プログラムをデータと同じメモリに置いて、順に読み出して実行する方式／1945 年前後に John von Neumann の名前で公表された報告書に由来し、以後ほぼすべての汎用コンピュータがこの型／利点は、プログラムを入れ替えるだけで別の仕事ができること（それ以前は配線のつなぎ替えが必要だった）／弱点は、計算する部分とメモリの間の行き来が渋滞になること（ノイマンボトルネックと呼ばれる）／**AI の計算で GPU や専用チップが効くのは、この渋滞を並列処理と広い帯域で緩めているから**、という形で今の話につながる
- **出典**：ブリタニカ「von Neumann machine」<https://www.britannica.com/technology/von-Neumann-machine>
- **書かないこと**：量子コンピュータ（J-33）、GPU の説明（J-77）
- 目安 reader_level 2-3 / importance C / figure_type structure

### J-50 AI 倫理

- **位置づけ**：J-50 台（倫理・安全・社会）の総論。個別の法律（J-53 著作権法、J-55 個人情報保護法、J-56 GDPR）の親にあたる
- **押さえる事実**：AI を作る側・使う側が守るべき考え方の総称で、公平性（偏りを持ち込まない）、透明性（何をしているか説明できる）、説明責任、プライバシー、安全性などが柱／議論が起きる典型は、学習データの偏りが結果の差別につながる、誰が責任を負うのか不明確になる、といった場面／**日本は罰則を伴う包括的な AI 規制法ではなく、ガイドライン中心**で進めており、総務省・経済産業省の「AI 事業者ガイドライン」が実務の指針になっている（2026-03 に第 1.2 版が公表）／**EU は AI Act という法律**を段階的に施行しており、リスクの高さで義務を分ける作りになっている／どちらが正解という話ではなく、進め方が違うと理解するのが読者にとっての要点
- **出典**：総務省・経済産業省「AI 事業者ガイドライン」<https://www.meti.go.jp/press/2024/04/20240419004/20240419004.html>、欧州委員会「AI Act」<https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai>

### J-55 個人情報保護法

- **位置づけ**：日本の読者にとっていちばん身近な法律。**AI に社内資料を貼ってよいのか**という日常の判断に直結する
- **押さえる事実**：日本で個人情報の扱いを定めた法律で、個人情報保護委員会が所管する／基本の考え方は、何に使うかを決めて伝えること、決めた目的の外に使わないこと、第三者に渡すときは原則として本人の同意が要ること／生成 AI との関係では「入力した内容が学習に使われるか」「本人の同意なく個人データを渡していないか」が実務の論点になる／**2026 年の改正法が 2026 年 7 月 10 日に成立、7 月 17 日に公布**された。施行は公布から 2 年以内（最長で 2028 年 7 月）で、**2026-08 時点ではまだ施行前**／改正では、AI 開発や統計作成の目的での利用に関する例外、16 歳未満の子どもの保護、課徴金制度の拡充などが盛り込まれている
- **出典**：個人情報保護委員会 <https://www.ppc.go.jp/>、e-Gov 法令検索（個人情報の保護に関する法律）<https://laws.e-gov.go.jp/law/415AC0000000057>
- **書かないこと**：GDPR（J-56）、AI 倫理の総論（J-50）

- **出典**：Turing, A. M. (1950) "Computing Machinery and Intelligence" <https://academic.oup.com/mind/article/LIX/236/433/986238>、Stanford Encyclopedia of Philosophy <https://plato.stanford.edu/entries/turing-test/>
